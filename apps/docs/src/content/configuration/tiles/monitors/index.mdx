# About

Monitors are probably the tiles you will use the most.

## Common Properties

All monitors have the following common properties that you can set:

| Property     | Type   | Description                                                                                                      | Required |
| ------------ | ------ | ---------------------------------------------------------------------------------------------------------------- | -------- |
| `key`        | string | Key to indentify this monitor in the database.                                                                   | Yes      |
| `name`       | string | Name of the monitor.                                                                                             | No       |
| `short_name` | string | Short name of the monitor. Shown instead of the name when the name does not fit the tile.                        | No       |
| `icon`       | string | Icon shown when the name does not fit the tile and `short_name` is not set.                                      | No       |
| `hidden`     | bool   | Leave the monitor off the board. It is still polled and listed in its [groups](/docs/configuration/tiles/group). | No       |

**Notes**:

> `key` must be unique on a per monitor type basis. A monitor listed in a [group](/docs/configuration/tiles/group)'s `members` needs a key no other monitor uses.

> If `hidden` is not set, the monitor is shown unless it belongs to a group and `hide_grouped_tiles` is enabled. See [Group](/docs/configuration/tiles/group#showing-members-on-the-board).

> If `name` is not set, the `key` will be used as the monitor name.

> Tiles show the full name whenever it fits, wrapping it at spaces and shrinking it slightly if needed. When it doesn't (for example on a phone), they show `short_name`, then `icon`, then the full name in small type, broken inside words. On small tiles the line above the name (address, uptime) is left out rather than cut off, and values that don't fit (for example an agent's disk usage) are dropped.

## What monitors record

Every check records whether the monitor was up, and when it failed, why. Agents from v0.8.0 also record:

| Monitor   | Recorded on each check                                                                                                                                   |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Host      | Ping latency.                                                                                                                                            |
| Agent     | The agent's own machine: CPU %, memory used and total, uptime, and usage of each configured disk. See [Agent](/docs/configuration/tiles/monitors/agent). |
| Website   | Response time, HTTP status code, redirect target, and the expiry of the TLS certificate the site presents.                                               |
| Container | State, Docker health check status, restart count, start time, image and version, last exit code, OOM kills, CPU % and memory used.                       |

Older agents keep working; their checks simply have no details.

## On the board

Each monitor tile shows its current value under its name: latency for hosts and websites, `CPU · MEM` for containers, how many checks passed for GitHub repos.

When something is wrong, the whole tile changes and says what the problem is in place of the value, so it reads at a distance and without relying on colour:

| Tile    | Looks like                         | Says, for example                                |
| ------- | ---------------------------------- | ------------------------------------------------ |
| Down    | Red, thick border, crossed circle  | `Down · HTTP 503`, `No report for 25 min`        |
| Warning | Amber, thick border, warning sign  | `Cert expires in 5 days`, `Disk / 93% full (+1)` |
| No data | Grey, dashed border, question mark | `No data yet`, `No check for 2 h`                |

A warning appears when a website's certificate expires within 14 days (or has expired), a container's health check fails, it is restarting, or it restarted in the last 24 hours, or one of a GitHub repo's checks failed; agents add their own (see [Agent](/docs/configuration/tiles/monitors/agent)). When there are several, the tile shows the first and how many more (`(+1)`); hover it, or open the dialog, for the full list. Tiles refresh every minute.

Clicking a tile opens its dialog with:

- **Link**: website dialogs link to the monitored URL and GitHub dialogs to the repository, opening in a new tab.
- **Now**: what the latest check recorded, for example status code and certificate expiry, container state, uptime, restarts, CPU, memory and image, or the result of each GitHub check.
- **Uptime**: the share of successful checks over the last 24 hours, 7 days and 30 days.
- **History**: charts (latency, or container CPU and memory) and incidents for the chosen range: 24 hours, 7 days or 30 days. Longer ranges are averaged into larger time buckets.
